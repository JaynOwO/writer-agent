# v0.0.8 dependency and compatibility inventory

The pnpm10.11.0 lockfile is generated by an actual package-manager installation against a local mirror of the owner's integrity-checked public npm archives. It is not hand-written and does not contain local mirror/file URLs. Development offline installation is not evidence of a direct registry internet installation. Frozen-lockfile remains mandatory; lifecycle scripts stay disabled by the existing .npmrc.

## Direct additions

- CLI: `@modelcontextprotocol/client@2.0.0` and `@napi-rs/keyring@2.1.0`.
- Test workspace: official client/core/server/node `2.0.0` plus `zod@4.6.5`. These support SDK fixture interoperability, not an unapproved installed service.
- Existing TypeScript5.8.3, @types/node22.19.7 and workspace links remain. LICENSE and NOTICE for Siglum are unchanged Apache-2.0; dependencies keep their own licenses.

The SDK runs as the protocol/client implementation behind host bounding and consent policy. The keyring wrapper lazy-loads the OS binding only after explicit need; Linux requires Secret Service instead of fallback to kernel keyring. Native prebuilt optional packages target specific OS/architectures. Absence/loader/backend failure is reported, never a reason to save plaintext keys. This inventory reflects npm package declarations, not a complete audit of transitive Rust/native-system components or a security endorsement.

## Validation distinctions

- Owner-provided preparation: Windows x64/Node24.18.0 install, basic SDK stdio, and isolated keyring binding roundtrip/reopen/cleanup passed. Not complete Siglum application validation.
- Linux application: actual installed SDK client with owned raw-wire and official SDK-server fixtures is tested; see delivery report. This is not independent third-party service conformance.
- Real OS-store sessions, real models/search and independent services require explicit separate probes. No private API credentials are included.
- SDK supports more capabilities than Siglum authorizes. OAuth, unsolicited callbacks, binary results, auto reconnect/hidden fallback and unsupported host-schema assertions remain outside this release.

## v0.0.9 desktop runtime

Electron44.4.1 is an official binary dependency pinned in apps/desktop/runtime-lock.json, not an npm package silently resolved at runtime. Both Windowsx64 and Linuxx64 ZIP hashes were checked against the prepared official assets. Upstream LICENSE and LICENSES.chromium.html accompany each portable distribution. Embedded Node/SQLite/NAPI are separately tested inside Electron; this does not certify Windows execution. The app has no new external renderer framework. pnpm genuinely includes the new dependency-free desktop workspace; MCP/keyring package versions remain as listed above.
