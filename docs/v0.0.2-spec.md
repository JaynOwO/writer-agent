# v0.0.2 — acceptance specification

Status: implemented in the v0.0.2 source delivery; remote merge, clean dependency installation, platform CI and real-provider smoke tests are separate validation steps.

## Goal and scope

A model can propose edits, but a model response cannot directly mutate a manuscript. Extend the existing revision core, retaining schema version 1 and all v0.0.1 behavioral tests. Adopt Apache-2.0 across the repository. No new third-party dependencies.

Three reviewable work groups (PR numbers are assigned by GitHub, not predetermined):

1. License, proposal protocol v1, typed provider errors and bounded HTTP transport.
2. OpenAI Chat Completions-compatible and native Ollama adapters; deterministic local HTTP tests.
3. CLI preview/send/review workflow, integration tests, synthetic provider demo, documentation.

## Acceptance

- LICENSE contains the complete standard Apache-2.0 text; NOTICE and every package manifest agree.
- Keep MockModelProvider available. Existing demo and original 61 tests continue to pass.
- Model IDs are explicit, not a hardcoded recommendation or account entitlement assumption.
- Only accept a complete JSON proposal with exact protocol version, document/revision identity, existing block IDs and verbatim original text. All validation failures save zero entries.
- No code fences, fuzzy replacement, automatic JSON repair, silent compatibility fallback, retries or automatic acceptance.
- Unknown fields, repeated target blocks, no-op edits, excessive edits/notes/bytes and invalid Unicode fail validation.
- The application independently validates the adapter result. The database checks the current head again after inference. Do not hold a transaction over the network.
- API keys are read from named process environment variables only when sending, never inserted into prompts, settings files, manuscripts, logs or database fields by the application.
- Local endpoints are loopback; normalize localhost to 127.0.0.1. Remote endpoints require explicit permission and HTTPS. Refuse userinfo, queries, fragments, cleartext remote endpoints and all redirects.
- Native Ollama: POST /api/chat, stream=false, format=JSON Schema, bounded num_predict.
- Compatible API: POST <base>/chat/completions, stream=false. Explicit json-schema/json/prompt and max_completion_tokens/max_tokens switches. Strict application validation always remains enabled.
- Classify 401/403, 429, other HTTP errors, refusals, truncation, network failure, timeout, cancellation and bad output. Never echo server error bodies or abort reasons.
- HTTP request and response have an 8 MiB hard limit. A single 120-second default deadline covers headers and body; configurable 10–600000 ms. Output-token default 4096, configurable 128–32768. This is not a dollar-cost guarantee.
- `writer suggest` previews without network traffic. `--send` is required for a provider request; remote use additionally requires `--allow-remote`.
- Successful send creates pending changes only. Model notes are labeled unverified and transient, not facts, source support or learned memory.
- CI and default tests use synthetic loopback servers, not commercial endpoints or downloaded models.
- `pnpm check`, `pnpm demo`, and `pnpm demo:provider` must pass. Real-provider smoke results must be reported separately, not inferred from fake-server tests.

## Outside this milestone

GUI, streaming, autonomous research, source snapshots, Claim Ledger, intent learning, sentence-level patches, MCP, Skills execution, cloud sync, hosted service and production security claims remain out of scope. Existing Markdown files are explicit imports/exports, not a second storage authority. A configured loopback server can itself forward to cloud inference; network policy here does not sandbox that server.
