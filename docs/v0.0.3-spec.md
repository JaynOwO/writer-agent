# Siglum v0.0.3 acceptance specification

## Authorized release boundary

Adopt the Siglum product name, separate English/Simplified Chinese READMEs, preserve Apache-2.0, and add the first local source/evidence-material workflow. Do not rename the GitHub repository, internal package scopes, existing CLI alias, .writer directory or delivery ZIP prefix. The current updater must continue to accept `writer-agent-v0.0.3-delivery.zip`.

This iteration is **Sources**, not a complete Research Agent: explicit URL/file intake, local search, immutable snapshots, exact excerpts, local notes, version-pinned paragraph links, selected model context and provenance. No global search provider, autonomous browser, Claim Ledger, verified semantic analysis, GUI, memory learning, Skills or MCP execution.

## User-visible acceptance

- English README.md and Simplified Chinese README.zh-CN.md have reciprocal language links and matching functionality/limitations.
- Root script `siglum` aliases the existing writer CLI; package/repository IDs remain compatible.
- URL intake previews with zero DNS/HTTP until `--fetch`. Only a bounded, explicitly selected public HTTP(S) resource is contacted.
- File intake preserves raw UTF-8 bytes and records static extracted text and reported metadata. Unknown authors/dates stay null.
- Snapshot identity and hashes are immutable. Refresh appends rather than replacing evidence.
- Excerpts are computed from saved text with exact line ranges, offsets and quote hashes. No fabricated quote text is accepted.
- Notes refer to a snapshot/optional matching excerpt and are never silently sent or learned as preferences.
- Local substring search works with literal Chinese queries and does not represent itself as internet/semantic search.
- Source links are pinned to document/block versions; same-block edits (even ABA) expose staleness. Unrelated blocks are preserved.
- `suggest --sources/--excerpts` previews selections, sends only on explicit permission, keeps sources untrusted, validates output and stores selected context atomically with pending proposals.
- Provenance records only "supplied-not-verified", not actual model use, citation correctness or support of a claim.
- No model response directly modifies manuscript text, source evidence or approval status.

## Data, migration and limits

New workspaces use additive schema v2. Source-free editing remains available on v1. The program never migrates writing workspaces as a side effect of code installation. `migrate` previews; `migrate --apply` requires an ordinary existing workspace and exclusive local lock, makes a verified SQLite backup, checks concurrent changes and adds tables transactionally. Existing manuscript rows/IDs/history must remain identical. Unknown schema/application IDs fail closed. Migration failures preserve a backup and no committed partial schema.

Raw source limit: 2,000,000 bytes. Extracted source text: 1,000,000 bytes. Selected context: at most 8 distinct items and 80,000 serialized UTF-8 bytes, no implicit truncation. HTML extractor is explicitly a limited static tokenizer, not a browser or full HTML5 parser. Excerpts refer to extracted-text lines, not PDF pages. Network intake accepts HTTP 200 text only, with 20-second total deadline, identity content encoding, 16-KiB headers and bounded streaming body; no redirect/retry/auth/cookie/JS execution. Source snapshots are stored in the same authoritative SQLite database as revisions, avoiding two-database provenance commits.

## Validation gates

Keep all prior regression tests and both existing demos. Add source parsing/hash/excerpt tests, persistence/integrity tests, v1 backup/migration rollback tests, source-context validation/concurrency tests, real loopback HTTP transport tests, SSRF policy/DNS pinning tests, CLI end-to-end source workflows, and mechanical bilingual checks. Default tests never call paid providers or public sites. `pnpm check`, `pnpm demo`, `pnpm demo:provider`, `pnpm demo:sources` must pass in the reported environment. CI targets Linux/Windows and Node 22/24; real Windows, fresh pnpm installs and live-site/model tests must not be claimed solely from Linux/synthetic results.

Package source only: no user workspaces, model credentials, node_modules, compiled dist, Git metadata or automatic updater credentials. Generate a format-1 guarded manifest against the verified v0.0.2 main commit and preserve the existing genuine lockfile.
