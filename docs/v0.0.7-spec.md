# Siglum v0.0.7 implementation and acceptance boundary

Source baseline: edf49218fb2c4686948e5e4b22e21cf9c97796e4 (v0.0.6). Product decision: combined Skills/MCP and research/context/citation enhancements, one format-1 delivery. Repository/package/data identity and Apache-2.0 unchanged.

## Implemented

Instruction-only immutable SKILL.md import, restricted scalar metadata, explicit activation and loaded reference ranges. Native bounded MCP client with explicit2026-07-28/2025-11-25 modes, actual stdio/HTTP JSON/SSE transports, tools/text-resource discovery, schema/descriptor hashes, separate connection trust and fixed-argument workflow authorization. No SDK installed; this is a deliberate constrained implementation rather than a claim of full standard compatibility. See extensions-protocol.md for exact unsupported fields/protocol features.

Extension config presence opts into full-saved-text indexing and question windows, literal relevance/diversity/URL/snippet/text dedup, recorded limitations and origin. MCP reads enter the existing workflow attempts/lease/quotas, with text imported atomically as external-service-unverified provenance. New guide-created schema6 runs opt in; old records keep absent fields and legacy behavior. Tools and chapters currently apply to new-article tasks; skills also apply to revision/audit.

Host-generated citation numbering/maps pin candidate/manuscript and source positions, associate source-entry quotation candidates (not proof for each claim), reject wrong/orphan references, save with adoption, and expose staleness. Optional chapter requests share the approved global outline/intent, freeze evidence per section, remap citations during local assembly, and pass through one bounded full-candidate review plus at most one revision. No unlimited context or sentence-level accept/revert.

## Scope refinements versus the planning artifact

The official SDK was evaluated but unavailable in the DNS-blocked build environment. This release instead provides a tested explicit native subset with no new dependencies, not a partially installed SDK. Dynamic model-selected tool planning is deferred: callers preselect exact method arguments for the stage. Full YAML, arbitrary JSON Schema assertions, OAuth/MRTR/subscriptions, binary tools and Skill scripts are unsupported. Unknown metadata remains unknown; no date/primary-source truth score is invented. Skills load only author-selected text/ref ranges, not an autonomous selection model. Citation positions use simple neighboring-text boundaries and source-entry quotes, not a complete Markdown AST/per-claim proof model. Source ranking/quality improvement is assessed on labelled-as-synthetic string fixtures; real quality remains unvalidated.

## Acceptance gates

Retain baseline regression suites/demos. Exercise one combined owned-Skill -> actual MCP stdio fixture -> tail evidence with qualification -> two chapter model HTTP fixtures -> host assembly -> critique -> explicit idempotent adoption. Test alternate HTTP/SSE+legacy modes, response/callback/schema errors, launch/descriptor changes, state ABA, permissions and secret boundaries, outcome-unknown/no automatic repeat, quota reservation, source/checkpoint/adoption transaction failures, v5 and prior migrations/backup, reference fanout, bilingual command parity, non-TTY/cancel and actual local PTY interactions where available.

All direct SQLite handles close before fixture directory cleanup. Clean final build logs specify Node/OS and exact dependencies. Default tests incur no paid API/model/search calls. Windows/Node24/independent MCP interoperability and genuine source/model research are separate unverified categories until actually exercised. No numeric semantic-quality guarantee. Preserve real lockfile, source/manifest hashes and existing updater format1; do not change installed updater or run it against user data. Explicitly select writer-agent-v0.0.7-delivery.zip at integration. Code install never migrates private workspaces.

## Data and authority

Additive schema6 preserves prior manuscript/source/ledger/memory/workflow rows and supports explicit verified backups. Skills/connections/decisions/catalogues/provenance/maps are append-only metadata; derived index cache is rebuildable. No model receives store/approval handles, root filesystem access or credentials. Stdio connection executes trusted installed code with user OS privileges: neither approval checks nor hashing is sandboxing. Unknown original schema, input staleness, unsupported tools or oversized output stops; it does not erase or overwrite the user's work.
