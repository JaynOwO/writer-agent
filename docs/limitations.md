# Known limitations — Siglum v0.0.4

1. **Development CLI, not a finished writing IDE.** No GUI, autonomous research, global web search, PDF/JS page rendering, automatic model downloads, Skills/MCP or learned memory.
2. **Review is experimental with real models.** Both task protocols and transports are implemented and tested with scripted responses. Real extraction/semantic accuracy has not been established. Schema validity and quotation correctness do not prove the interpretation. Providers may fail to produce exact offsets, especially in long/Unicode text; no automatic repair/retry is performed.
3. **Scope is explicit.** Selected-block analysis cannot conclude a claim disappeared everywhere. Whole-document review requires --document-scope and must fit limits. Mappings may recognize paraphrases/relocation, but are model opinions, not a robust autonomous argument graph.
4. **No truth certification.** Claims are annotations. Manual confirmation affirms annotation accuracy, not real-world truth. Evidence relations concern only selected material and are attributed. Missing assessments are not-assessed; conflicts are not majority-voted. Important claims are explicit constraints, not an inferred intent contract.
5. **Block-level editing remains.** Findings can point inside a sentence, but accept/revert still replaces a whole block. No arbitrary word rollback, automatic rebase or structural moves. After same-block interference old operations fail rather than overwrite newer work.
6. **Conservative freshness.** A later document revision, pending-operation change or relevant ledger decision makes the review historical. Reverting text does not reset revision identity. A source refresh leaves old analyses about pinned old snapshots, not new material. Feedback is version-bound, separate from text decisions.
7. **Prototype storage.** SQLite remains authoritative; Markdown is explicit import/export, not live sync. Full snapshots/reports duplicate text, are synchronous and unencrypted. No background backup, compaction or malicious-owner tamper resistance. List operations return at most 100 reports; claim lists refuse beyond 1000 occurrences per document.
8. **Explicit migration.** New workspaces use schema v3. v1 editing and v2 sources remain usable. Analysis requests require explicit migrate --apply with verified backup/cooperative lock after closing other sessions. Code updates never migrate private data; unknown schemas fail closed. Backups contain private data and must not overwrite a live SQLite/WAL database.
9. **Existing source limits remain.** Static UTF-8 HTML/Markdown/text only, immutable raw/extracted snapshots and limited metadata extraction. No browser, logins, compression, redirects or guarantee of site permission/authenticity. DNS/IP pinning is not a full network sandbox. Source search is exact local substring search.
10. **Provider limits remain.** Ollama native non-streaming and Chat Completions compatibility, not every model/API or Responses API. A loopback service may relay to cloud. API keys only come from named process environment variables; no automatic .env or secret vault. --send/--allow-remote remain explicit. Billing may continue after cancellation.
11. **Software tests are not semantic benchmarks.** The 80 bilingual cases and labels are AI-authored drafts. The scoring scaffold performs no inference and rejects unreviewed labels unless explicitly marked draft evaluation. It cannot authenticate supplied prediction provenance. Report coverage, abstentions and false alarms separately; do not publish an accuracy claim from fixtures.
12. **Mechanical docs checks only.** Version, command, link and feature-marker parity is checked, not translation quality. Supporting developer docs are partially bilingual. Claims/review guides are paired.
13. **Rights and brand.** Standard Apache-2.0 applies to code, not to imported sources/manuscripts/model weights/services. No exclusive name, domain or trademark clearance is claimed.
