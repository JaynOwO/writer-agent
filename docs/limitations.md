# Known limitations — Siglum v0.0.6

1. **CLI preview, not a finished IDE.** Numbered bilingual guide is implemented; no GUI/desktop package, streaming, unrestricted autonomous agents, PDF/JS rendering, Skills/MCP or model downloads.
2. **Memory is explicitly controlled, not passive learning.** Draft intent/preferences require an explicit model call and author activation. Scope selection is deterministic, not semantic retrieval; profile names/priority are author choices. Rejected wording does not prove a general dislike, even with an explanation.
3. **No semantic certainty.** Analysis results and style/intent warnings are fallible model assessments. Exact span validation and fixture tests are not evidence of real-model fidelity. The 80 evaluation labels are drafts pending human review; no live accuracy result is claimed.
4. **Block-level text changes.** No per-word/sentence accept/revert, structural moves or automatic rebase. Same-block newer versions conflict even after text returns to a previous spelling.
5. **Bounded selection.** Up to20 profile rules,3 individually authorized examples and24000 serialized UTF-8 bytes. Required/explicit overflow refuses. Intent20 rules/exceptions20; exports200 active rules/500000 bytes. Feedback examples are bounded whole-block pairs; choose smaller examples manually when too long.
6. **Conflict handling is structural.** tone/sentence-style/max-characters compare exact values. Same winning-layer conflicts and missing required overrides refuse. Free prose conflicts are not comprehensively detected. Required means retained/explicit waiver, not guaranteed model compliance. Character count uses code points, not graphemes/words. Title scope has no separate title generation command.
7. **Privacy and history.** Data/backups/exports are unencrypted. Disable does not erase historical snapshots or service copies. Exports omit examples/history by default but cannot redact secrets manually entered in rule text. No secure erase, global sync or new credential store. A loopback model may proxy to the cloud.
8. **Migration explicit.** New schema5; legacy1 editing,2 sources,3 analysis,4 memory remain usable. Workflow features require backed-up explicit migration; updating code does not migrate writing. Close other sessions; never overwrite open databases with backup files. Older binaries refuse newer schemas.
9. **Prototype persistence.** SQLite remains authoritative; Markdown is explicit import/export. Full revision/context copies duplicate data; no compaction or automatic backups outside migration. Synchronous DB work needs isolation in a future GUI. A file owner can bypass hash/trigger safeguards.
10. **Static web intake.** Small UTF-8 tokenizer, not full HTML5/browser/article rendering. No redirects/compression/logins/JS/PDF. DNS/IP pinning reduces risk but is not an OS/network sandbox. Source supplied to a model is not proof of use, citation or support.
11. **Runtime and validation.** No new third-party runtime packages. node:sqlite can warn on Node22. CI targets Node22/24 on Linux/Windows; each release must report actual checks separately. Offline exact-dependency builds do not prove fresh npm installation. Real interactive Windows and real models require explicit validation on those targets.
12. **Failure and compatibility.** No retries/model repairs/credential fallback. Old reports retain missing memory, not invented historical preferences. Such reports cannot attest to rules added later. Failures do not store an apparently successful analysis; author decisions and successful request history remain distinct.

13. **Fixed foreground templates.** No arbitrary workflow files/code, background daemon, GUI, browser automation or Skills/MCP. Real web search is only in new-article research; existing-document templates use selected saved material. Replies regenerate a private outline after explicit refresh/consent and consume the same budget; public search/page caches can be reused. No unlimited chat loop.
14. **Research coverage.** Tavily basic search needs the user's own key. Snippets remain discovery records. Selection is deterministic first-per-host then result order, not a reliability classifier or exhaustive literature review. Automatically fetched material supplies at most its first 40 complete extracted-text lines within 8000 bytes, disclosing omission. A long first line can leave a page saved but not supplied. Explicit source selections retain their existing 8-item/80000-byte bound. Review the coverage, gaps and citations before writing.
15. **Candidate review.** New drafts have no fabricated original-revision diff. Draft review uses exact candidate/source quotes but remains fallible; B is not automatically subjected to another review. A/B comparison uses prefix/suffix spans, not minimal semantic diff or word-level rollback. Source footnotes are resolved by host to snapshots, not certificates of source support.
16. **Resume and cost.** One serialized worker per run uses a 45-second renewable, generation-fenced lease. Outcome-unknown requests require explicit duplicate-call acknowledgement. No end-to-end exactly-once or strict monetary cap is promised; provider processing/charges may outlive local cancellation. Attempt budgets are reserved before dispatch and never refunded silently. Author waiting time is excluded; a crashed lease conservatively charges until expiry. Successful saved outputs are reused only for the same validated inputs. Budget changes revoke consent but preserve matching results; input refresh creates a new epoch, retaining old outputs as history.
17. **First-party implementation, not real-service evaluation.** Search and model adapters are exercised with real HTTP on synthetic loopback fixtures in default tests. They have not been validated with a genuine Tavily account or real inference model in this delivery. Windows/Node24/CI also require independent runs. No model quality or accuracy claim follows from the number of tests.
