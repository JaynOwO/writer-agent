# Siglum v0.0.4 — implementation and acceptance boundary

Base: `JaynOwO/writer-agent` main `82bb474df4af9ea87e33cc50b0f0744247116ace`, v0.0.3. This document describes the implementation in this source tree. Execution evidence belongs in the delivery validation report; this file does not assert Windows/CI/live model success.

## Implemented scope

Manual claim annotation, optional extraction candidates, version/UTF-16-pinned occurrences, author confirmation/correction/importance, independent evidence assessments, exact prefix/suffix text observations, a separate opt-in semantic-review task, candidate mappings, scoped findings, pinned source references, immutable reports and independent author feedback. A host-built proposed snapshot is never accepted merely by being reviewed.

Product/repository/package/data IDs, Apache-2.0 and format-1 updater contract remain unchanged. Dependencies and the genuine pnpm lockfile remain unchanged. English/Chinese README and paired review/source guides remain coordinated.

## Three trust levels

1. Mechanically checked identities, text coordinates, hashes and revision preconditions.
2. Model interpretations, labelled model-assessment-not-verified.
3. Explicit author annotation/evidence/report decisions, not universal truth certification.

Candidate confirmation concerns the wording, not its truth. Supplied source context, paragraph links, human evidence assessments and model evidence assessments stay distinct. A missing assessment becomes not-assessed; insufficient selected evidence is not absence of all possible evidence. No arbitrary confidence percentage or acceptance recommendation is treated as an authority.

## Existing behavior preserved

The original editing Proposal Protocol v1, before text/block ID/version checks, transactional pending proposals, independent-block accept/reject/revert and source snapshots remain in place. Neither extraction nor review accepts/rejects text, changes source snapshots or learns preferences. Sentence anchors do not add sentence-level editing.

Source-free legacy operations remain available on schema v1 and existing source operations on v2. Claim/review features require v3. Explicit migration previews, retains and verifies a SQLite backup, refuses unknown versions/concurrent changes and adds tables in one transaction. Code updates never search for or migrate private workspaces.

## Analysis transaction and protocol contract

Separate task methods use the existing Ollama/native chat and OpenAI Chat Completions-compatible transports. Model data has no database/filesystem/approval/tool handles. The CLI previews scope, destinations and selected source identities; --send authorizes only this call, remote also requires --allow-remote/HTTPS. No retry, repair, fallback, web source fetching or private-note inclusion.

The host retains a separate copy of request state, projects compatible pending edits in memory, validates model-local refs/exact coordinates/evidence quotes, rechecks document/change/claim/source state after HTTP and saves atomically. Extraction saves candidate rows with its run; review candidates remain within the proposed report, never inserted as actual future document occurrences. Failed requests save no successful report. Historical reports are readable offline and marked stale conservatively. Alternate briefs require new runs rather than silently changing old inputs.

## Acceptance gates

- Manual and model-candidate claim creation, multiple occurrences per claim, correction and protected-claim selection.
- Unicode/CRLF/repeated-quote integrity, surrogate boundary rejection and exact non-semantic changed-span reconstruction.
- Independent extraction/review schema validation, duplicate-key parsing, response identity, meaningful cardinalities and scoped references.
- Missing/contradictory/partial evidence handling without truth claims; separate user feedback for findings, mappings and assessments.
- No manuscript mutation from analysis/feedback; stale input and transaction faults leave no partial report/candidates.
- Source refresh retains old pinned reports; manuscript/annotation/change-state updates stale semantic reports; text ABA does not revalidate them.
- Legacy schema-v1/v2 backed-up migration to v3 preserves prior rows/IDs and rolls back on injected schema failure.
- All previous regressions and demos, bilingual README checks and new fake-provider demo continue to run.
- New demo uses real loopback HTTP transport with explicitly scripted findings and ends in REVIEW_DEMO_OK.

Run `pnpm check`, `pnpm demo`, `pnpm demo:provider`, `pnpm demo:sources`, `pnpm demo:review`. CI is configured for Linux/Windows and Node 22/24. The updater calls check and the two old demos; the review demo is also exercised by tests inside check. No installed updater modifications are required.

## What remains limited or unvalidated

This is not a GUI, autonomous researcher, general argument graph, full author-intent model, factual verifier, sentence-level patch engine or learned memory/Skills/MCP runtime. Exact text diff is one changed span per block, not a minimal edit script. Schema validity cannot validate a model's explanation. Successful runs are retained; failure transcripts are not. Model names/usage are service configuration/returned metadata, not attestations or billing records.

The evaluation folder contains 80 synthetic AI-authored draft labels, 40 Chinese and 40 English, and an offline scoring scaffold. None are human-reviewed ground truth. The scorer needs explicit permission for draft-label scoring and never invokes inference. Passing software tests is not a semantic accuracy result. No live semantic-quality claim is part of this release without a separately documented, authorized real-model run.

A bounded report is persisted only after success. An extraction report does not become stale solely because it appended its own candidates; its manuscript revision still governs freshness. Different selection/brief means a different run, not a globally mutable brief. Report lists return the latest 100 runs, and claim listings refuse more than 1000 occurrences; pagination and long-term compaction are not implemented.
