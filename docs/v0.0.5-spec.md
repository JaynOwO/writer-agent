# Siglum v0.0.5 — implementation and acceptance boundary

Implemented scope derives from the owner's decisions: **1C 2C 3C 4D 5C 6C 7C 8B**. Baseline is v0.0.4 commit `d3bc9b5d346e491a46ad45adba0548079f3f0001`, tree `f57d371f8ea7f712ffd3092f9d0872ab760bb0c9`. The delivery records actual validation separately from this specification.

## Delivered

- Manual/template intent cards and independently authorized AI drafts. Confirm before activation; draft evidence locations/suggestions/questions remain inspectable.
- Local workspace profiles, versioned scoped rules, active/manual versus candidate/model/imported status, selective confirmation, corrections and disabling.
- Optional structured rejection categories linked to immutable decisions. No motive learning from reasonless rejection. Explicit feedback selection for candidate drafting; examples independently opt in.
- Deterministic profile/language/task selection, priority/stable ordering, visible budgets/exclusions; 20 profile rules, 3 examples and 24000 serialized UTF-8 bytes. No retrieval-model/embedding dependency.
- Request exceptions > article > profile for exact comparable fields, exact required-rule waivers, same-layer conflicts and no automatic free-text semantic conflict resolution.
- Usage snapshots and freshness checks for writing/review, no DB transaction over inference. Unrelated profiles do not invalidate current analysis. Historical inputs remain unchanged.
- Local literal/code-point checks, optional memory-aware semantic review, unchanged explicit manuscript accept/reject/revert.
- Numbered English/Simplified Chinese terminal guide using existing service functions, cancellation/nonTTY behavior, profile/document/candidate selection without copied IDs, privacy-conscious import/export.
- Additive schema4 migration with verified backup, old v1/v2/v3 functionality and explicit refusal for unsupported future versions.

## Actual boundaries

This is an interactive CLI, not a GUI. Free guidance is not a formal logic solver or guaranteed style enforcement. No passive learning, automatic old-file scanning, cross-workspace sync, fine-tuning, vectors, Skills/MCP or automatic provider escalation. Title is a rule scope, not a new generation feature. Model-generated suggestions must still be reviewed for fidelity: literal quote matching cannot establish intent accuracy. Rejected examples are bounded whole-block contrasts when explicitly selected; larger cases need manually chosen smaller examples. Imported rules remain candidates even if the source export was active.

The guide takes an explicit workspace path and lists/imports its documents. Source import/refresh and schema migration are still separate capabilities, not automatic research. Provider configuration is reused only in the current guide session. No new credential store. The terminal blocks nonTTY input and does not use a full-screen UI dependency.

The status record supplies latest profile-rule states plus immutable older versions, not a complete event-stream framework. There is no safe-erasure promise; disabling does not remove old request snapshots/backups/provider copies. Free text in a rule can contain private information, so export is not automatic redaction.

## Invariants and regression acceptance

Candidates/drafts do not enter ordinary guidance; manual confirmation is explicit. Activating only some candidates leaves the rest pending. Required/explicit overflow fails without truncation. Wrong scope/evidence/unknown fields and fabricated quotes are refused. A one-request exception cannot rewrite active intent/profile. Memory feedback never approves manuscript text or certifies claims. Capture changes during inference reject the result; successful pending changes/use context commit atomically. Appended reports remain readable without silently injecting new fields into old histories.

All prior source/core/provider/analysis tests remain. Add tests for scoping, quotas, required-conflict handling, intent/candidate transitions, stale requests, data integrity, failure rollback, version1/2/3 migrations with old-row preservation, private examples/import/export, actual loopback task requests, errors/timeouts/cancellation, interactive service paths and terminal sanitization. Close all extra SQLite handles before temporary-directory cleanup; no test weakening to hide Windows file locks.

`pnpm check` runs documentation parity, typecheck, build and all tests. Keep demo, demo:provider, demo:sources and demo:review, add demo:memory with MEMORY_DEMO_OK. The memory demo is also covered in tests so the existing updater need not learn a new command. CI independently invokes all demos for Linux/Windows and Node22/24. Report actual vs unrun OS/install/model tests; no accuracy claim from fixture pass counts.
